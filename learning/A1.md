## The checkpoint, and what passing sounds like

Say all seven, cold. The right-hand side is the shape of a passing answer, not a script.

1. **What a token is.** A chunk of text from a fixed vocabulary, often a word fragment, chosen by a tokenizer trained on frequency. "Powershell" and "P0w3rsh3ll" are different numbers of tokens. The model never sees letters, only token IDs.
2. **What the context window physically is.** A fixed-length sequence of token vectors that attention runs over. Nothing outside it exists to the model. Everything inside it, system prompt, your message, retrieved docs, and tool results, is the same kind of thing: tokens in one sequence.
3. **Why the model just predicts the next token.** Training is: given a sequence, predict the next token, adjust weights, repeat over the internet. Everything else (chat, reasoning, tool use) is that one operation, run in a loop, shaped by fine-tuning.
4. **Base vs. instruction-tuned.** A base model continues text. An instruction-tuned model was further trained on conversation examples (and then with feedback) so it continues text *as an assistant*. The assistant is a persona the base model learned to simulate, not a separate program.
5. **What temperature does.** The model outputs a probability for every possible next token. Temperature reshapes that distribution before sampling: near zero picks the top token almost every time, higher flattens it so unlikely tokens get chosen more. It changes variety, not knowledge.
6. **What a system prompt is, and why it is not a privileged security boundary.** Text placed at the start of the context that the model was trained to weight heavily. It is still tokens in the same sequence as untrusted input, with no enforcement behind it. "Never reveal X" is a request, not a control. Anything that needs enforcing has to be enforced outside the model.
7. **Why hallucination is structural, not a bug.** The model produces the most plausible continuation, and training and evaluation reward a confident guess over "I don't know." A fluent wrong answer and a fluent right one are produced by the same process. It will not go away with a bigger model; it is managed, not fixed.

The last two are the ones that matter for your job. They are why a "guardrail in the prompt" is not a guardrail and why an AI-written triage note needs a human verdict.

---

## Why this stage matters for a SOC analyst

Every AI feature you will ever be asked to assess, and every AI tool that lands in the SOC, rests on these seven facts. Stage A3's attack surface (injection, the lethal trifecta) is only obvious if you have internalized that the context window is one undifferentiated stream of tokens. And the "can AI do my job" question has a real answer once you know what the model is actually doing.

## The path, in order

### 1. Finish the Deep Dive. (Karpathy, 3h31, shift time, in progress)
**Deep Dive into LLMs like ChatGPT**, Andrej Karpathy, YouTube. You are mid-video. Watch the rest at 1.25x. It covers the full stack: pretraining on internet text, tokenization, base models, supervised fine-tuning into an assistant, hallucinations and why, then reinforcement learning and "thinking."
**Extract:** items 1, 3, 4, and the first half of 7. When he demos the base model continuing text, pause and say out loud what the difference from the assistant is. That is checkpoint item 4.

### 2. Tokenize your own logs. (15 minutes, shift time, hands-on)
Open **Tiktokenizer** (tiktokenizer.vercel.app). Paste in, one at a time: a Windows event log line, an encoded PowerShell command, a base64 blob, a URL with a long query string, a Sigma rule. Watch how each splits.
**Extract:** item 1, for real. Notice that obfuscated strings shatter into many tokens, that the model is "reading" something quite different from what you see, and why a model can miss things hidden in encodings. This is the first place AI security and SOC work touch.

### 3. See the architecture. (3Blue1Brown, chapters 5 to 7, about 25 minutes each, shift time)
**Transformers, the tech behind LLMs** (chapter 5) · **Attention in transformers, step-by-step** (chapter 6) · **How might LLMs store facts** (chapter 7). At 3blue1brown.com/lessons/gpt, /attention, and the series page. Watch 5 and 6 in full. Chapter 7 is optional but short.
**Extract:** item 2. After chapter 6 you should be able to say "the context window is the set of token vectors attention runs over, and attention is how each token reads from every other token in that window." That is the physical picture.

### 4. Read why hallucination is structural. (OpenAI, Kalai et al., September 2025, 20 minutes, shift time)
**Why Language Models Hallucinate**, the blog post at openai.com/index/why-language-models-hallucinate. The paper is on arXiv (2509.04664) if you want the proofs; the post is enough.
**Extract:** the second half of item 7. The core claims: generating a valid answer is harder than checking one, and standard training and evaluation reward guessing over admitting uncertainty, so a model that generalizes at all will hallucinate. Say the student-exam analogy back to yourself.

### 5. Read why the system prompt is not a boundary. (Simon Willison, 45 minutes, shift time)
His **prompt injection series** at simonwillison.net/series/prompt-injection. Read the original 2022 post that coined the term, then the **lethal trifecta** post. Skim the rest of the series for the shape of real incidents.
**Extract:** item 6, and a preview of Stage A3. The key line to own: the model cannot reliably distinguish instructions from data, because both arrive as tokens in one context. Therefore any "don't do X" in the system prompt can be overridden by text that arrives later. His defensive rule is the one to remember: if untrusted content and private data are ever in the same context, make sure there is no path out.

### 6. Feel temperature. (15 minutes, home time or any playground, hands-on)
Any chat playground with a temperature slider, or Ollama locally. Same prompt ("write one sentence describing a failed SSH login"), run three times at temperature 0, then three times at 1.5.
**Extract:** item 5. At 0 you get near-identical outputs; at 1.5 you get variety and eventually nonsense. That is the distribution being flattened. Nothing about what the model knows changed.

### Optional, only if hungry (home time)
- **Let's build GPT: from scratch, in code, spelled out** (Karpathy, 1h56). Builds a transformer in code from an empty file. Do this if the 3Blue1Brown pictures left you wanting the mechanics.
- **Let's build the GPT Tokenizer** (Karpathy, about 2 hours). The whole of item 1 in code. Only if tokenization fascinated you in step 2.
- **The Illustrated Transformer**, Jay Alammar. A reading alternative to the 3Blue1Brown videos.

## Self-test (say these cold, to a person or to your camera)

- The seven checkpoint items, in your own words, no notes.
- A vendor says their copilot "can't leak data because the system prompt forbids it." What have they actually built, and what would you ask next?
- Why does a model confidently produce a CVE number that doesn't exist? Why won't the next model version fix that?
- Paste a base64 payload into a prompt. Why might the model behave strangely with it, and what does that mean for using an LLM to triage encoded commands?
- A retrieved document and the user's question are both in the context window. From the model's point of view, what is the difference between them?
